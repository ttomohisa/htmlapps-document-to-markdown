# Offline / Local Processing Verification

Document to Markdown v1.0.0 is intended to run with no runtime external network access.

## Release verification

1. Run `build-standalone.bat` on Windows.
2. Confirm `scripts/check-repository.ps1`, `scripts/verify-standalone.ps1`, and `scripts/verify-self-extract.ps1` pass.
3. Open `dist/index.html` directly with `file://`.
4. Disable the network in browser developer tools.
5. Convert representative `.docx`, `.pptx`, `.xlsx`, `.pdf`, `.txt`, `.html`, `.csv`, and `.tsv` fixtures.
6. Confirm Markdown preview, copy, and `.md` save continue to work.
7. Confirm the Network panel shows no application request for the selected file or generated Markdown.
8. Repeat with `dist/index.self-extract.html`.
9. On a smartphone-sized viewport, open Help and scroll to the final item; also verify the bottom page tabs do not cover content.

## Batch / mobile check

1. Select `sample.docx`, `sample.pptx`, `sample.xlsx`, and `sample.pdf` together.
2. Confirm exactly four queue rows appear and each reaches a terminal state without another file blocking the queue.
3. Select each completed row and confirm its Markdown / Preview / Info result changes to that source file.
4. Add another supported file while processing is active and confirm it joins the queue.
5. Use **Cancel remaining** during an active multi-file batch and confirm queued files become Cancelled and the processing row eventually clears.
6. Use **Save all as ZIP** and confirm there is one Markdown file per successful result, extracted `images/` assets remain under that document folder, duplicate source basenames are de-duplicated, and `unzip -t` reports no CRC error.
7. At 320px and 360px widths, confirm the file queue has no horizontal scrolling, long filenames do not expand the viewport, row actions are tappable, and the fixed mobile bottom bar does not cover content.
8. Confirm selecting up to 20 files is accepted, while additional files or a batch above 300 MB is rejected with a readable message.

## HTML safety check

Use an HTML fixture containing `<script>`, inline event handlers, remote images, and remote styles. Confirm none execute or load. The generated Markdown may preserve links or image references as text, but preview must not fetch the referenced resource.

## Storage check

Convert a document, reload the page, and confirm the document content/result is not restored. Language preference may persist.

## DOCX check

Open the committed DOCX fixture and confirm headings, paragraphs, lists, tables, links, and the embedded PNG convert without a network request. Confirm Markdown contains a relative `images/image-001.png` reference and the image ZIP action appears. Confirm encrypted or malformed packages fail safely and do not leave the UI stuck in the processing state.

## PPTX check

Open the committed PPTX fixture and confirm slide order, titles, inherited bullet levels, tables, external hyperlinks, Speaker Notes, embedded image extraction, and chart warnings convert without a network request. Confirm PPTX source-boundary comments do not appear in the rendered preview. Save the image ZIP and confirm it contains the generated Markdown plus `images/image-001.png`.

## XLSX check

Open the committed XLSX fixture and confirm visible worksheets are emitted in workbook order, the hidden worksheet is excluded and counted, dates/booleans/cached formulas are converted, and an uncached formula is preserved as formula text with a warning. Confirm merged-cell, drawing/image/chart, comment, and external-reference warnings appear without any network request. Also verify a normal XLSX generated by an Excel-compatible library with `/xl/...` relationship targets converts successfully.


## PDF check

Open `tests/fixtures/sample.pdf` with the Network panel offline. Confirm all three pages convert in page order, `<!-- Page N -->` markers are present in the Markdown source but hidden from preview, English and Japanese text are extracted, link annotations do not cause a request, and PDF layout warnings are shown where detected. Confirm the embedded dependency count is `1` and there is no request for the PDF.js module, worker, CMap files, CDN content, or linked URL.

Open `tests/fixtures/scanned.pdf` and confirm the conversion fails with the explicit scan/image-only PDF message explaining that OCR is not yet supported. The file must not be uploaded or sent to an OCR service.

## Conversion quality report

1. Convert `tests/fixtures/sample.pptx`, `sample.xlsx`, and `sample.pdf`.
2. Open the Info tab and confirm findings are grouped by Converted / Check recommended / Not converted / Partial failure.
3. Confirm slide, sheet, or page locations appear where the fixture exposes a location-specific issue.
4. Confirm no network request is made while opening the report.
